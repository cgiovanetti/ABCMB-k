2026-10-22 (evening) — pure-LINX route: dense-grid output + log-log interpolation inside LINX; batched Jacobian
------------------------------------------------------------------------------------------------------------
Developed in a scratch copy of the vendored LINX (scan/.mm/linxdev/, gitignored) so the pending 48 h job keeps
the validated on-disk stage; NOTHING APPLIED to abcmb/linx or scan/bbn_stage.py yet. Diffs for review:
scan/.mm/linxdev/vendored_dense_loglog.diff (abcmb/linx), /pscratch/sd/c/carag/LINX/dense_grid_loglog.diff (LINX
main, on top of rho_extra_norm.diff; dry-run clean on main + fix, NOT on the grace checkout, which lacks the
fix), scan/.mm/linxdev/bbn_stage_new.py (the stage without _regrid, BG_N_OUT, AB_MAX_STEPS 16384, batched
Jacobian with per-lane fallback).
(1) background.py: SaveAt(steps=True, dense=True); the outputs are n_out (4096) log-spaced times from the first
step to the event step read from the dense interpolant, end points pinned exactly (exp(log t) can land one ulp
past the last step, where the interpolant holds garbage: whole-batch NaN for some inputs before the pin); no
padding, no inf tail. (2) abundances.py: a(t), T_g(t) interpolated as log against log t (power laws). Measured
(scan/.mm/linxdev/val12_pinned.log, steps_dev.log, main_port/steps_main.log): YHe roughness along
Delta_Neff_init 1.5e-5 -> 5.4e-8 (omega_b 1.7e-8), YHe_BBN 0.244238 = the converged reference (0.244236 at
background rtol 1e-10), Neff 2.829201, 0.45-0.54 s per cosmology (no penalty), network steps 1191 -> 1157 at
rtol 1e-6 and 5119 -> 4958 at 1e-8 (fewer rejections; ~5000 at 1e-8 everywhere, so AB_MAX_STEPS 8192+). On
LINX main's own stack (linx312, jax 0.8.3) the port gives YHe_BBN 0.244236 = the vendored value to 2e-6: the old
1.4e-4 "LINX main vs abcmb.linx" offset was each code's raw-grid interpolation bias. Note: at rtol 1e-8 the
network needs ~5000 steps on LINX main with or without the port (default max_steps 4096 is exceeded).
(3) Batched Jacobian: with the dense grid a vmapped two-jvp over 4-16 lanes is finite in every equinox error
mode and host-device count (batched_jvp_matrix.log), where the raw-grid code raised for any batch > 1. Larger
batches (61-64 lanes) and three specific lanes alone still raise "A linear solver received non-finite input" from
optimistix's implicit-function-theorem jvp of the network's implicit stage (optimistix/_ad.py: the tangent of the
Newton residual is non-finite), flaky across compiled programs (host-device count, fused vs separate jvps), the
same mechanism behind the original jacfwd NaN; in EQX_ON_ERROR=nan mode one such lane nan-s its whole chunk
(equinox reduces the predicate over the batch), so the drafted stage's 64-lane chunks fell back to per-lane
(no speed gain yet; correctness fine: stage_new_test.log). diffrax stop-gradients the step-size factor, so the
step sizes carry no tangent; the culprit component / fix: see below.
Culprit and fix (tangent_comp.log, nothrow_test.log): a batch with an identically ZERO input tangent raises too,
and so does a fixed (input-independent) grid, so it is not what enters the network. diffrax calls the implicit
stage's optx.root_find with throw=False, but optimistix's implicit-function-theorem jvp (optimistix/_ad.py)
runs lineax.linear_solve with throw=True: a Newton stage that diverged, which the primal rejects and retries
smaller, raises inside the tangent. Fix in the stage (3 lines, no LINX change): lineax.linear_solve made
non-throwing process-wide; the garbage tangent of a rejected stage is masked by the rejection like its primal.
Result: 64-lane batched Jacobian 64/64 finite, 1.25 s per row (vs 5.7 s per lane, nearly serial), batched =
per-lane to 1e-4 (dNeff/ddn to 5 digits). The same mechanism very likely produced the all-NaN gradient block
of the timed-out run in ABCMB's implicit perturbation solves; the patch covers those too. Worth reporting
upstream (diffrax/optimistix: throw=False should reach the adjoint's solve).
Status: NOT applied (the 48 h job 60057736 is pending on the regrid stage and picks up on-disk code). To switch
the production stack: scontrol hold 60057736; git apply scan/.mm/linxdev/vendored_dense_loglog.diff
scan/.mm/linxdev/stage_new.diff; a --qos=debug shakeout of scan/profile_prod_linx_dneff.slurm (the batched
Jacobian has not run inside the driver on GPU); scontrol release. Expected: gradient blocks ~4-5x faster
(1.25 vs 5.7 s per row), YHe at the converged value, no re-grid. Port to LINX main: dense_grid_loglog.diff
(tested on LINX's own stack: linx312, jax 0.8.3).

2026-10-22 (late afternoon) — LINX background bug (inert radiation normalized at the first saved step); tolerance decision
----------------------------------------------------------------------------------------------------------------------
The background-tolerance scan for the LINX stage (scan/.mm/linx_bg_mid.log, linx_neff_sm.log) showed LINX's final
Neff for Delta_Neff_init != 0 moving with the tolerance without converging (x = -0.823: 2.8095 / 2.8155 / 2.8206 /
2.8238 / 2.8262 / 2.8264 at rtol 1e-6 .. 3e-11; the standard-model 3.0444 is stable). Decomposition
(linx_neff_drift.log): the neutrino part and the entropy ratio R = (a_0 T_0 / a_last T_last)^4 = 0.26190 are
stable, the inert-species part is not: abcmb/linx/background.py normalized rho_extra_vec at a_vec[0], and with
SaveAt(steps=True) that is the END OF THE FIRST STEP, not the initial state the ODE itself uses (lna_init), so
rho_extra came out (a_1 / a_0)^4 ~ 4% too large at the default tolerance and only shrank with the first step.
Fixed (one line, normalize at exp(lna_init)): Neff(x = -0.823) = 2.82916 / 2.82920 / 2.82917 at rtol 1e-7 / 1e-8 /
3e-10, converged to 4e-5, inert part = x R exactly; Neff = 3.0444 + 0.2619 x (the documented 0.272 was the bug:
(4/11)^(4/3) = 0.2605 plus incomplete decoupling). YHe is unchanged to the bit (with t(T), a(t) given, the
network never reads rho_NP). LINX main (/pscratch/sd/c/carag/LINX, linx/background.py:200) and ../ABCMB carry
the same line and are NOT fixed: every LINX Neff for Delta_Neff_init != 0 so far is off by ~4% of the extra
species' contribution (-8e-3 at x = -0.8, +1e-2 at x = +1). Still open, now tolerance-independent: dNeff/dx by
jvp 0.2624 vs secant 0.2614-0.2616 (0.35%): the jvp of the small decoupling piece has the wrong sign
(d log(aT_nu)/dx +4.7e-5 vs secant -3e-5..-4e-5), ~1e-3 absolute in the slope, ~0.01 sigma here.
Tolerance decision (the request was to tighten rather than re-grid): a tight background does reach the
re-grid's YHe smoothness (3e-10: 9.7e-8) but at 3.0 s per cosmology (vs 0.49) and 18.7 s per Jacobian lane
(vs 5.7; the per-lane programs run nearly serially, host callbacks), ~70 min per 312-row gradient block, an LM
phase beyond the 48 h job; 5e-10 is already 2.8 / 17.6 s and 2e-10 3.1 / 19.1 s, no middle ground. With the
Neff drift gone the only reason for a tight background was YHe, which the re-grid handles at 1.25x. Production
stays re-grid + network 1e-8 + default background, now on the fixed normalization; job 60057736 released.

2026-10-22 (afternoon) — deflation removed from the profile driver
------------------------------------------------------------------
The deflated Newton walks (Farrell, Birkisson & Funke 2015; HANDOFF item 16) are gone from
scan/profile_prod_ad.py and scan/lm_tools.py. Reason: for a profile likelihood the question is only whether a
lower minimum exists at a grid point and whether the branch is followed across grid points; the spread starts,
the flags, the branches from every distinct spread-start minimum and the lower envelope answer that. Deflation
finds stationary points (saddles included, which the PSD GN curvature cannot tell from minima), gives no more
certainty than the starts (both are local exploration), and in practice only ever triggered on noise: _v3
flagged nothing, the _v4linx run burned hours on walks from LINX-noise stalls and produced 7 artefact "new"
points. Removed: deflated_rows, _classify_rows, the MS_ROUNDS round loop (now one pass: flags -> branches),
PA_MS_ROUNDS / PA_DF_MAXIT / PA_DF_P / PA_DF_ALPHA / PA_MS_FORCE / PA_MS_BRANCH_FROM, the ROUND / status /
barrier row columns (npz: rows_round, rows_status, rows_barrier), lm_tools.deflation / deflate_step /
deflated_resid and their tests. Row kinds are warm / spread / branch (KIND 0 / 1 / 2; old row tables with
KIND 2 = deflation are not compatible, none are live). pytests/test_lm_tools.py (5) and test_profile_toy.py
(2) pass on the toy double well / toy bimodal profile.

2026-10-19 (night) — Profile driver: multimodality (spread starts, flags, deflation walks, branches, union intervals)
--------------------------------------------------------------------------------------------------------------------
HANDOFF TODO 14-18, branch multimodal in the worktree ../ABCMB-k-multimodal (off development 5487640; a worktree
because another session was validating development in this checkout). New scan/lm_tools.py holds the pure-numpy
pieces: the projected LM step (moved out of the driver), deflation (Farrell, Birkisson & Funke 2015, SIAM J. Sci.
Comput. 37, A2026), eigen-spread starts, minima clustering + flags, the union of below-threshold regions and the
multimodality test of a profile's points; pytests/test_lm_tools.py runs them on a toy double well (7 tests, CPU).
profile_prod_ad.py, by item:
  (14) MS_K=3 spread starts at MS_NPTS=6 grid points per POI (both ends included), +-MS_SPREAD=2 profile sigmas
       (sqrt(2/lambda_k)) along the softest eigen-directions of the warm GN matrix on the row's free dims,
       shortened along their direction to stay inside the box. They run in the same lockstep; a point's profile
       value is the lowest chi2 over its starts; the interval-stability stop waits for them (MS_WAIT=1). The old
       uniform-random PA_MULTISTART mode is gone.
  (15) flags per grid point: a stalled start; converged starts > MS_DX=0.5 scaled sigma apart (distinct minima);
       converged starts at one point > MS_DCHI2=0.1 apart in chi2.
  (16) flagged points: deflated Newton walks from the point's warm + spread starts (those within MS_DX of a known
       minimum replaced by spreads around the best minimum on its own GN matrix), every known minimum deflated at
       once, M = prod_i (|x - x_i|^-p + alpha). The step is the undamped GN step d rescaled to d / (1 - grad(log
       M).d) (Sherman-Morrison on the deflated Jacobian M J + g grad(M)^T), capped at STEP_MAX and projected; no
       damping and no acceptance test -- a bounded walk of <= DF_MAXIT=10 steps; walks still going are finished
       by ordinary LM (BR_MAXIT). End states: new / recaptured (within MS_DX of a known minimum) / escaped (on the
       +-XBOX box) / stalled (ABCMB failed) / maxit. Default alpha=0, unshifted: a full Newton step toward a known
       minimum is reversed at any distance, so the walk leaves the basin along the ray through its start (a start
       on the far side escapes; the +- spread pairs put one on each side). Farrell's shift alpha=1 limits the
       reach to 1 scaled sigma and beyond it the step is amplified past the minimum instead of reversed, so the
       walk hops around it: in the shakeout (run with alpha=1 before the default was changed) every walk came
       back recaptured or unfinished. The GN matrix is PSD, so a saddle cannot be told from a minimum by its
       curvature; each new stationary point is reported with its chi2 against the known minimum and the chi2
       along the straight segment between them (7 value calls; the barrier it shows is an upper bound).
  (17) each new stationary point (<= MS_BRANCH_MAX=4 per POI, lowest chi2 first) seeds a branch: an ordinary LM
       run from it at every grid point of its POI (BR_MAXIT=10, interval stop on the branch's own profile). The
       profile is the lower envelope over every row; MS_ROUNDS (1) repeats flags -> deflation -> branches with the
       branch rows included.
  (18) poi_interval returns (lo, best, hi, regions): regions = the union of the regions below threshold
       (lm_tools.union_regions, the bound-aware thresholds unchanged), lo/hi its outer ends; the stop also
       requires the number of regions to be unchanged over its window. A profile whose points show two minima
       separated by a barrier > MS_DCHI2 is interpolated (pchip) instead of quartic-fitted (_interval_mode).
  Outputs: the per-POI npz keeps the old fields on the envelope rows and adds regions1/2/95, flag/flag_reason,
  n_starts/n_minima, minima_x/chi2/kind and the full row table (rows_j/kind/start/round/status/x0/x/chi2/gnorm/
  converged/stalled/at_box/barrier); the png shows every row above the envelope and shades a multi-region 68%
  union. The phases checkpoint a row table (profile_prod_ad_TABLE<tag>[_r<rank>].npz, resumable per phase) next
  to the LM state file (which now also stores X0).
Shakeout (interactive 60018759, 1 node / 4 GPUs, scan/.mm/shake.sh: the massless-nu copy of the rc config, h,
5 points, 3 spreads at 3 points, PA_MS_FORCE=1, PA_MS_BRANCH_FROM=any, MAXIT 4 / DF_MAXIT 2 / BR_MAXIT 2):
spread starts 3.1 scaled sigma out on average; lockstep 4 iterations 3055 s (5.5 min/iteration at 14 rows; the
5 base rows converged at it1, the spreads walk back at STEP_MAX=1 per iteration and 3/9 were under GTOL by it3);

2026-10-14 — Staged AD gradient: directions vmapped inside each stage's jvp (branch grad-vmap-dirs)
-----------------------------------------------------------------------------------------------
Why: the 2026-10-13 fork-vs-upstream bench showed upstream's jacfwd 2.75-5.9x FASTER than the
fork's staged gradient. The question behind it (can batched values replace gradients for the
profile?) is no: a gradient-free batched minimizer needs ~(2n+1)=15 points per iteration and
2-3x the iterations, so batched values must be ~30-45x cheaper than a gradient; the fork's
values were ~20x cheaper than its own gradient and ~7x cheaper than upstream's. So fix the gradient.
Cause: staged_cl_and_grad (scan/batched_grad.py) looped the P directions and every jax.jvp
re-solved the full primal -> 1 + P primal solves per gradient.
Fix: stack the directions on a leading axis and push them through ONE jvp per stage, vmapped
over that axis (jvp_stage(..., n_dirs=); out_axes=(None, 0)), and read the primal Cls off the
same jvp. One primal solve per gradient. dir_chunk (driver PA_GRAD_DIRCHUNK) chunks the
directions as a memory fallback; direction-stacked tangents shard on axis 1 (_dir_shardfn_from).
Return layout unchanged (list[P] of (dTT, dTE, dEE)); staged_chi2_and_grad / the driver untouched
apart from the knob. Driver PA_AD_BCHUNK default 64 -> 32 (see memory).
Bench (scan/.grad_bench/ in the ABCMB-k-grad worktree; copy of fvu/bench_fvu.py, k path only;
production specs, P=7, 1 A100-40GB, warm s/cosmo, peak GB):

  B=8, dir_chunk=4 (4+3, two primal solves): 59.2 / 9.6 -- chunking is a poor trade.

BACKGROUND:
The existing single-cosmology path is limited by the slowest k mode
under its vmap-over-k — every k pays the worst-case diffrax step count.
For frequentist analyses where 1000s of cosmologies are evaluated, that
worst-case-tax compounds. The proposed flipped order (vmap over a batch
of params at fixed k, loop/scan over k) should give a tighter step-count
distribution at fixed k → faster per-params at large B.

    behaving batch-composition-dependently under vmap. Different
    k-mode batches → different worst-case step counts → different
    actual stepping → trajectories disagree at the per-mode level but
    all stay within the configured rtol_large_k_PE = 1e-4 envelope.

  Hard evidence (bench/chunking_debug_report.md):
    The "max_abs 8.6e-1 between chunk and full-vmap" was on
    quantities of norm ~1e4 — i.e., ~1e-5 relative, fine for spectrum
    integration. smoke_convergence at rtol_large=1e-4 shows both
    full-vmap and chunked agree with pure-single-k integration to
    ~1e-6 relative. Tighter rtol brackets confirm convergence.

  Implications:
    - Chunking works; the spectrum/PT downstream agreement is the
      contract that matters (already at 1e-5 in
      smoke_batched_pipeline.log).
    - We rolled back the python-loop workaround in
      make_output_table_batched after this diagnosis.
